왜 이 시리즈가 필요한가

SAP 컨설턴트는 기능을 아는 것과 그것을 고객에게 이해시키는 것 사이의 간극에서 실패한다

BC/GR/SAC 시리즈가 "무엇을 아는가"를 다룬다면, PC 시리즈는 "아는 것을 어떻게 고객이 이해하도록 전달하는가"를 다룬다. 대상은 발표 경험이 적은 주니어 컨설턴트이며, 목표는 대중 강연 스킬이 아니라 워크숍·설계 리뷰·Steering Committee·교육 현장에서 실제로 쓰이는 설명력이다.

좋은 컨설턴트는 많이 말하는 사람이 아니라, 복잡한 내용을 쉽게 이해시키는 사람이다.

Architecture View

네 개의 소유 패턴이 서로 다른 단위 위에 쌓여 있다

Constitution이 소유한 것과 각 챕터가 소유한 것은 서로 다른 레이어다. 하나가 다른 하나를 대체하지 않는다.

Constitution §3 — Standard Explanation PatternConcept → Mechanism → Business Value → Customer Impact → (Optional) Recommendation — 무엇을 설명할 것인가
PC04 — Explanation Delivery SequenceAudience Context → Why This Matters → Pattern 적용 → Business Decision — 설명 하나를 어떻게 전달하는가
PC05 — Question Handling PatternQuestion → Clarify Intent → Answer Core Point → Connect Business Context → Confirm Understanding — 질문 하나에 어떻게 대응하는가
PC06 — Presentation Facilitation PatternObjective Alignment → Audience Engagement → Discussion Control → Decision/Next Step — 세션 전체를 어떻게 운영하는가
PC07 — Presentation Learning LoopPrepare → Practice → Present → Reflect → Improve — PC01~PC06을 어떻게 반복 훈련으로 전환하는가 (신규 Pattern 아님, Closure 역할)
✓ 검증 완료 (Ownership Collision Check)
전 챕터 HTML의 Primary Example/Concept 뱃지와 Constitution §7 Registry를 전수 조사한 결과, 동일 개념이 두 챕터에 Primary로 중복 배정된 사례는 없다. Constitution 소유 개념(Standard Explanation Pattern)이 챕터로 내려와 재정의된 사례도 없다.
